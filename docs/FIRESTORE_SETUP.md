# Firebase Firestore Setup for Carbon Offset Records

## Overview
The application now saves carbon offset records to Firebase Cloud Firestore after successful Stripe payments. Each line item in the cart is stored as a separate record in the `offsets` collection, allowing you to track air travel, home energy, and car trips individually while maintaining the same transaction ID.

## Firestore Collection Structure

### Collection: `offsets`

Each document in this collection represents a single offset item purchased. Here's the schema:

```javascript
{
  userEmail: string,              // Email provided by the user at checkout
  transactionId: string,          // Stripe Payment Intent ID (same for all items in a transaction)
  offsetType: string,             // "car", "air", "home", or "quick"
  carbonPounds: number,           // Total carbon offset in pounds
  carbonKg: number,               // Total carbon offset in kilograms
  cost: number,                   // Cost of this offset item in USD
  description: string,            // Human-readable description of the offset
  origin: string | null,          // Starting location (for trips)
  destination: string | null,     // Ending location (for trips)
  distance: number | null,        // Distance in miles
  unit: string | null,            // Unit of measurement (e.g., "miles")
  travelers: number,              // Number of travelers (default: 1)
  timestamp: Timestamp,           // Server timestamp (auto-generated by Firestore)
  createdAt: string               // ISO timestamp string
}
```

## Implementation Details

### 1. **Firebase Configuration** (`src/firebase.js`)
- Updated to initialize Firestore (Cloud Firestore)
- Exports `db` instance for use in other modules

### 2. **Firestore Utilities** (`src/utils/firestore.js`)
New functions added:

#### `saveOffsetRecords(userEmail, transactionId, cartItems)`
- Saves each cart item as a separate offset record
- Called automatically after successful Stripe payment
- Returns array of created document IDs

#### `getUserOffsets(userEmail)`
- Retrieves all offset records for a specific user
- Ordered by timestamp (newest first)

#### `getTransactionOffsets(transactionId)`
- Retrieves all offset records for a specific transaction
- Useful for viewing all items purchased in a single transaction

### 3. **Cart Component Updates** (`src/components/Cart.jsx`)
- Added email input field for users to provide their email
- Email validation before checkout
- Passes cart items and user email to StripeCheckout component

### 4. **Stripe Checkout Updates** (`src/components/StripeCheckout.jsx`)
- Now accepts `cartItems` and `userEmail` props
- After successful payment, automatically calls `saveOffsetRecords()`
- Gracefully handles Firestore save errors (doesn't fail the payment)

## How It Works

1. **User adds offsets to cart** - Each item (air travel, car trip, home energy, quick offset) is added with its CO2 amount and cost

2. **User proceeds to checkout** - Required to provide their email address

3. **Payment processing** - Stripe payment is processed

4. **Firestore save** - After successful payment, each cart item is saved as a separate document:
   - All items share the same `transactionId` (Stripe Payment Intent ID)
   - Each item has its own `offsetType` for tracking purposes
   - User email is recorded for future lookups

5. **Thank you page** - User is directed to thank you page with payment details

## Usage Examples

### Query records by user email:
```javascript
import { getUserOffsets } from '../utils/firestore';

const offsets = await getUserOffsets('user@example.com');
// Returns array of all offsets for this user
```

### Query records by transaction ID:
```javascript
import { getTransactionOffsets } from '../utils/firestore';

const transactionOffsets = await getTransactionOffsets('pi_1234567890');
// Returns all offsets purchased in this transaction
```

## Firestore Security Rules

After deploying to production, configure Firestore security rules to:
- Allow users to read only their own offset records
- Allow the backend to write offset records
- Prevent unauthorized access

Example rules:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /offsets/{document=**} {
      // Allow read if user email matches
      allow read: if request.auth.token.email == resource.data.userEmail;
      // Allow write from backend only (via authenticated requests)
      allow write: if request.auth != null;
    }
  }
}
```

- `FIREBASE_STORAGE_BUCKET`
- `FIREBASE_MESSAGING_SENDER_ID`

## Tracking Individual Offset Types

With this implementation, you can now:

- **Track air travel separately**: Filter `offsets` collection where `offsetType == "air"`
- **Track home energy separately**: Filter where `offsetType == "home"`
- **Track car trips separately**: Filter where `offsetType == "car"`
- **Track quick offsets**: Filter where `offsetType == "quick"`

All while maintaining the transaction relationship through `transactionId`.
